# Техническая модель Localis

## Реальный «ядро»-подход

Локальная LLM в Ollama — это модельные веса + inference runtime. Добавить в весовой файл браузер, системные разрешения, HTTP-клиент и генератор файлов одной вставкой кода нельзя: это не исполняемые модули модели. Localis оставляет Gemma и runtime неизменными, а связывает их официальным локальным HTTP API Ollama.

```text
Electron renderer (UI, без Node)
       │ узкий IPC через contextBridge
       ▼
Electron main (Ollama API, approvals, filesystem scope, browser lifecycle)
       ├── http://127.0.0.1:11434/api/chat  (локальная модель)
       ├── публичные web endpoints           (только после подтверждения)
       ├── выбранная Localis Workspace       (ограниченные файловые инструменты)
       ├── ComfyUI/A1111 localhost API        (необязательно)
       └── ffmpeg                             (необязательно)
```

## Цикл агента

1. История пользователя нормализуется до ролей `user`/`assistant`; системные и tool-сообщения от renderer не принимаются.
2. В `/api/chat` передаются system prompt, история, последнее сообщение, список функций Ollama и `stream: true`.
3. Поток NDJSON отображается в приложении. Tool calls собираются из native Ollama `message.tool_calls`.
4. Каждый tool call показывается пользователю с именем, аргументами и категорией риска. Без одноразового согласия действие не исполняется.
5. После инструмента результат добавляется как сообщение `tool` и возвращается модели для финального ответа.
6. Ограничения: максимум 8 итераций и 12 вызовов инструмента на пользовательский запрос; файловые операции только внутри workspace.

## Изоляция и доверие

- Renderer: `contextIsolation`, `sandbox`, `nodeIntegration: false`, строгая CSP, whitelisted IPC-каналы.
- Веб-страницы показываются в отдельном `WebContentsView` без preload/Node API; browser session отклоняет разрешения и pop-up окна.
- Fetch веб-текста разрешает только публичные `http(s)` URL; запрещает loopback/private IP и перепроверяет redirect-адреса. HTML скрипты не исполняются, извлекается ограниченный текст.
- Файловые операции валидируют относительные пути, реальные пути после symlink и размер файла. Workspace выбирается пользователем.
- Вызов оболочки требует отдельного подтверждения и ограничен временем/выводом; Electron не является OS-level sandbox для процесса, запущенного пользователем.
- Изображения/видео локальны и выключены без локального backend/ffmpeg. Секреты для облачных сервисов не требуются и не хранятся.

## Поведение и память

Обычные диалоги хранятся в JSON в профиле приложения. Отдельный инструмент `remember` сохраняет краткую заметку после согласия; system prompt включает до 20 последних заметок. Поиск похожих заметок пока сделан простым ограниченным списком, а не векторной базой. Никакой записи в веса Gemma нет.

## Поддерживаемые артефакты

- UTF-8 текст/исходный код/HTML/CSS/JS/JSON/CSV/YAML и т. п.
- DOCX на `docx`, PDF на `pdfkit`, XLSX на `exceljs`, PPTX на `pptxgenjs`.
- PNG через локальный A1111/Forge API или ComfyUI API.
- MP4 (H.264) из рабочих изображений через ffmpeg.

Произвольные бинарники, Autodesk/Adobe-проекты, текст-в-видео и полноценное дообучение модели не выдаются за встроенные возможности: для каждого нужны свои генераторы, модели или системные SDK.

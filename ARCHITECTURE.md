# Техническая модель Localis

## Модель и приложение

Ollama выполняет inference для неизменённых файлов модели. Localis соединяет её с локальными инструментами и выбранными внешними API через Electron main process. Gemini/Gemma/Ollama не получают файловый доступ сами по себе, а коннекторы не меняют и не дообучают веса.

```text
Electron renderer (UI, без Node API)
       │ ограниченный IPC через contextBridge
       ▼
Electron main (настройки, разрешения, run lifecycle, файловый scope)
       ├── Ollama /api/chat (локальная модель, tool calling, streaming)
       ├── проверенные публичные web endpoints
       ├── выбранные GitHub / Google / Instagram API
       ├── настроенные MCP Streamable HTTP servers
       ├── необязательные cloud AI providers
       ├── локальные файлы и документы
       ├── AUTOMATIC1111 / Forge / ComfyUI loopback API
       └── ffmpeg (необязательно)
```

## Цикл агента

1. Renderer отправляет текст, историю user/assistant, ID проекта, выбранные в чате connector/provider IDs и ID разрешённых вложений. Main повторно фильтрует подключённые IDs; история с ролью system/tool из renderer не принимается.
2. Main формирует system prompt из выбранной модели, активного проекта, локальной общей памяти, включённых skills и реально выбранных сервисов.
3. Ollama получает `/api/chat` с native tool schemas и `stream: true`. NDJSON text и tool calls попадают в Activity sidebar.
4. В режиме Ask каждый инструмент сопровождается одноразовым экраном с summary и аргументами. В Full access пользователь заранее подтверждает отдельное предупреждение; последующие tool prompts автоматически принимаются и файловый доступ может выйти за workspace.
5. Результат инструмента возвращается модели как `tool`-сообщение; ошибки остаются в activity log и ответе, не превращаются в ложный успех.
6. Лимиты — до 8 agent rounds и 12 tool calls за запрос. Повтор запроса Ollama ограничен; облачный fallback требует включённой настройки, сохранённого ключа, выбора провайдера и согласия на передачу контекста (кроме Full access).

## IPC и границы доверия

- Renderer: `contextIsolation`, `sandbox`, `nodeIntegration: false`, CSP с локальными скриптами, узкий список функций preload и проверка отправителя IPC.
- Удалённые страницы открываются в отдельном `WebContentsView` и отдельной Electron session без preload/Node API; pop-ups и браузерные разрешения отключены. Веб-инструменты проверяют протокол, DNS/IP и redirects; приватные диапазоны запрещены.
- MCP endpoints хранятся в настройках, bearer credentials — в локальном vault. HTTP допускается только для loopback. Перед сетевым вызовом remote endpoint проверяется как публичный; redirects с auth заголовком запрещены.
- GitHub agent import не клонирует репозиторий: получает ограниченный набор небольших Markdown-файлов через GitHub API и хранит их как текстовые инструкции. Скачанный исходный код не запускается; пользователь может просмотреть, выключить или удалить импорт.
- Plugins хранятся как текстовые instructions и не становятся исполняемыми JavaScript-модулями.

## Файловая безопасность

- Обычный режим разрешает файл-инструментам работать внутри выбранного workspace/project. Пути нормализуются, проверяются realpath и symlink; запись не создаёт каталоги за пределами workspace.
- Full access — не OS sandbox. Он разрешает main process использовать пути за пределами workspace и запускать одобренные по смыслу инструменты/команды с полномочиями пользователя; ошибки/вредоносные команды могут повредить данные.
- Процессы ограничены таймаутом и выводом. Папка проекта проверяется как потомок workspace; проекты получают отдельный корень и отдельные чаты.

## Секреты, настройки и память

- Настройки, история, память, проекты, plugins и GitHub-agent registry хранятся в Electron userData профиле Windows.
- API keys, OAuth refresh/access tokens и connector/MCP bearer tokens хранятся в `secrets.enc` через `safeStorage`; при недоступности системного шифрования Localis отказывается сохранять секрет открытым текстом.
- Обычные сообщения могут содержать личную информацию; при включённой интеграции выбранный контекст передаётся соответствующей службе. Внешний AI получает только выбранные текстовые сообщения; общие форматы токенов маскируются. Чувствительные Windows DPAPI-секреты обычно не переносятся на другой профиль/ПК.
- Shared memory — ограниченная текстовая сводка недавних обращений/результатов плюс отдельные пользовательские notes. Данные локальны, не меняют веса Gemma и очищаются через настройки.

## Выходные форматы и внешние зависимости

- UTF-8-файлы, DOCX (`docx`), PDF (`pdfkit`), XLSX (`exceljs`), PPTX (`pptxgenjs`).
- Анализ CSV/TSV/JSON/JSONL выполняется локально и не изменяет источник.
- Картинки — локальный A1111/Forge или ComfyUI API; MP4 — локальные кадры + ffmpeg. Text-to-video и fine-tuning не включены.
- Windows installer собирается Electron Builder в NSIS x64; тесты запускаются `node --test` и GitHub Actions.

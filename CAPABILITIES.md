# Карта возможностей локального AI в 2026 году

Здесь важно разделять **способности самой модели** и **инструменты приложения вокруг неё**. LLM генерирует текст и, если обучена этому, предлагает tool calls. Файловый доступ, браузер, поиск, память, изображения и команды выполняет отдельный доверенный слой приложения. «Вшить интернет в весовой файл» нельзя: это меняет архитектуру/обучение и всё равно не заменяет сетевой runtime.

| Возможность | Модель Ollama | Слой Localis | Что необходимо локально |
|---|---|---|---|
| Русский и другие языки | Знания языков из весов конкретной модели; качество зависит от checkpoint | Сохраняет язык пользователя и не обещает язык сверх модели | Подобрать multilingual-модель и проверить её на своих задачах |
| Анализ, рассуждение, код | Качество, скорость и контекст модели | Переписка, потоковая выдача и выбор установленной модели | Память/VRAM под выбранную квантизацию |
| Веб-поиск | У модели нет автоматически актуального интернета | DuckDuckGo search и чтение извлечённого публичного HTML с источниками | Интернет; каждое действие видно и подтверждается |
| Браузер | Не часть весов | Отдельное desktop-окно Chromium/WebContentsView, URL, назад/вперёд, reload | Интернет; Node API и системные разрешения для сайта закрыты |
| Вызов инструментов | Нужна модель с поддержкой function/tool calling | Native Ollama `/api/chat`, stream и цикл tool → результат → ответ; до 8 итераций/12 операций за запрос | Точная модель Ollama, которая действительно поддерживает tools |
| Анализ изображений | Только vision-capable модели и совместимое API | Вложения изображения передаются в Ollama локально | Модель с image-input; одной текстовой Gemma недостаточно |
| Генерация изображения | Генератор изображений — отдельная модель, не текстовая LLM | AUTOMATIC1111/Forge API либо ComfyUI API, результат в workspace | SD/SDXL/Flux checkpoint и достаточная VRAM |
| Документы и файлы | LLM составляет содержимое/код | TXT, Markdown, исходный код, JSON/CSV, DOCX, PDF, XLSX и PPTX | Встроенные библиотеки; сохраняет в workspace |
| Создание приложений | LLM формирует проект и код | Запись файлов + запуск сборки/тестов через подтверждаемые команды | Node.js/Python/compiler и зависимости проекта |
| Генерация видео | Специализированная text-to-video модель нужна отдельно | Создание MP4/H.264-слайдшоу из кадров через ffmpeg | ffmpeg; картинки от локальной модели/пользователя |
| Речь, музыка, real-time voice | Отдельные ASR/TTS/audio-модели и runtime | Не включено в текущую версию | Для расширения нужны локальный ASR, TTS и политика доступа к микрофону |
| «Самообучение» | Ollama inference использует уже обученные веса; приложение их не меняет | История и 20 последних сохранённых заметок дают persistent context | Для реального fine-tuning нужны набор данных, обучающая среда, GPU/VRAM и отдельный процесс оценки |
| Работа с GitHub | Сама модель не получает полномочия к аккаунту | Публичные сайты можно искать/читать; проект можно собирать командами после согласия | Git и отдельное подтверждение каждой команды; GitHub-токены не запрашиваются |

## Почему это максимально практичная форма «локального агента»

1. **Модель остаётся заменяемой.** Любая доступная в Ollama модель может использовать общий набор инструментов. Не нужно модифицировать Gemma и рисковать исходными весами.
2. **Права отделены от генерации.** Текст модели не исполняется напрямую. Приложение проверяет аргументы, показывает действие и ждёт явного одноразового подтверждения.
3. **Возможности соответствуют локальным ресурсам.** Модель для текста, vision, изображений и видео — разные workload; их VRAM/скорость/лицензии различаются. Нет честного способа обещать одинаковое качество на любом ПК.
4. **Результаты проверяемы.** Пользователь видит адрес сайта, относительный путь, команду и созданный артефакт. Работа с файлами ограничена выбранной папкой.
5. **Без зависимости от проприетарного кода.** Реализована интеграция по открытым API/протоколам, а не копирование внутренностей коммерческих моделей или агентов.
